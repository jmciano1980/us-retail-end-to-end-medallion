### ADR-002: Use a Permissive PostgreSQL Source Schema

**Date:** 2026-07-22

**Status:** Accepted

#### Context

The synthetic retail dataset intentionally contains approximately 1% data-quality issues.

Examples include:

* NULL invoice dates
* NULL payment methods
* Missing customer references
* Invalid product references
* Other intentionally generated source-data issues

The initial PostgreSQL schema contained primary-key, foreign-key and CHECK constraints that prevented some of these records from being loaded.

This would cause the source system to reject the very data-quality conditions that the downstream Medallion pipeline is intended to detect and process.

#### Decision

The PostgreSQL source schema will be **permissive with respect to business-data quality**.

The source tables will not enforce business rules that would prevent intentionally invalid source records from being ingested.

In particular, business-level validation such as:

* Referential integrity between business entities
* Quantity validation
* Discount validation
* Required customer relationships
* Transaction consistency
* Product validity

will be evaluated in later Medallion stages rather than enforced during source ingestion.

Technical metadata and database requirements may still be enforced where they are necessary for the operation of the source database.

The PostgreSQL schema therefore represents an **imperfect operational source system**, rather than a validated analytical dataset.

#### Consequences

PostgreSQL can contain:

* NULL business values
* Duplicate business records where generated by the source
* Invalid references
* Invalid business values
* Other intentionally generated data-quality issues

These conditions are preserved during extraction to Parquet and ingestion into Databricks RAW.

Data quality is addressed downstream:

```text
PostgreSQL
    ↓
Parquet
    ↓
Databricks RAW
    ↓
Bronze
    ↓
Silver Data Quality Rules
    ↓
+-------------------+
|                   |
Valid            Invalid
  |                 |
  ↓                 ↓
Silver          Quarantine
  |                 |
  +--------+--------+
           ↓
         Gold
```

Quarantined records will retain sufficient information to support:

* Error classification
* Error descriptions
* Source lineage
* Data-quality reporting
* Error-correction analysis

This separation prevents ingestion processes from hiding source-data problems and allows the project to demonstrate an end-to-end data-quality management process.
